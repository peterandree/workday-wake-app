闹钟可靠性

Workday Wake 如何经过工程化设计，在小米、三星、华为和其他 采用激进电池管理的设备上持续响铃 — 以及你能在手机上检查什么。

为什么有这个页面

在原生安卓设备（比如 Google Pixel）上，一款写得好的闹钟应用 通常都能正常工作。但在相当大一部分安卓装机量上并非如此：多家 厂商的电源管理功能会杀掉后台应用、悄悄丢掉已排定的 闹钟，或阻止应用自启 — 往往 而且完全不从通知应用“有东西被取消了”。

关键问题正是这种不对称：你的闹钟没了，应用却永远不知情。 Workday Wake 为此做的所有设计都围绕一个问题： 如果一个机制被清除了，哪个其他机制会发现？

本页面就是这段工程设计的公开可读版本。它解释这些设备 实际会做什么、应用如何应对，以及万一出了问题，你如何在应用内 查看并共享诊断数据。各品牌设置步骤和 应用自带的指引来自同一来源；如果本页面与应用 出现分歧，以应用内 设置 > 可靠性 界面 为准。

敌意环境实际会做什么

机制常见于对天真的闹钟应用的影响
最近任务上划杀进程 / 强制停止Xiaomi (MIUI/HyperOS), Samsung (One UI)已注册的闹钟被清空，且不回调应用
缓存进程清除（“内存清理”）Xiaomi, Oppo/ColorOS, Samsung进程无预警死亡；应用在进程层面的计划全部落空
后台冻结 / 自启动限制Xiaomi (HyperOS/MIUI Autostart), Oppo/ColorOS (DuraSpeed)闹钟可能照常送达，但响铃的进程被冻结 — 或应用永远无法自行重启
电池优化被设为“受限制”原生安卓也有，外加厂商电池管理闹钟被延迟或批量投递；即使最高优先级的闹钟 API 也可能被饿死
深度 Doze / 低活跃度存储桶所有安卓；阈值因系统定制而异除非闹钟 API 获得豁免，否则投递被推迟
开机广播被拦截（自启动）Xiaomi/MIUI, HyperOS重启后闹钟不会重新注册，直到用户允许自启动
备份恢复和系统升级All Android与上划杀进程一样：注册无声无息消失

我们叠加的层层防线

上面的每一种系统皮肤都无法被单一机制覆盖，因此 Workday Wake 叠加了多道独立防线。每一层都假设上一层可能已被破坏：

预防你的闹钟通过 setAlarmClock() 调度 — 这是安卓提供的最高优先级闹钟 API： 不受 Doze 限制、在系统时钟界面可见，即使进程已死也会送达。 它还会在状态栏显示小闹钟图标；这是应用正常工作， 不是 Bug。
恢复重启后、时区变更后、每次应用启动时， 以及由定期离线维护任务重新注册闹钟 （精确闹钟权限每 8 小时检查一次）。这些任务不依赖 进程是否存活，因此能重建厂商清除的一切。
监督在需要的设备上，一个小的第二进程 每 6 小时与主进程互相签到。如果一方 13 小时无动静，另一方就重新注册闹钟。这层默认 关闭（占内存）；对已知行为的品牌或发生第一次可靠性事件后 自动开启，且绝不会悄悄再关闭。
检测与自愈每个闹钟记录它 预期响铃的时间；每次实际响铃也记录在案。如果预期 的闹钟没响，应用记为一次漏响，并从闹钟列表使用的 同一数据源悄悄重新排定 — 甚至在你熟睡时完成。
诚实上报如果检测机制本身似乎 失效（守护连续三次无签到），应用会发出一条清晰可见的通知， 告知闹钟可靠性已下降 — 而不是假装一切正常。

如果一层存在的意义只是接住上一层的失败， 那它就在正常履职 — 漏响、自愈和上报都被如实记录，绝不隐瞒。

各品牌设置步骤（来自应用内置指引）

应用内置指引（受影响设备上的设置 > 可靠性）， 包含各厂商的精确步骤。以下为简版 — 若设置界面点名应用， 请在你的启动器里把“Workday Wake”替换为应用名称：

品牌 / 系统步骤（与应用内设备电池指南一致）
小米 / MIUI、HyperOS允许自启动；在自定义权限中启用“锁屏显示”和“后台弹出界面”； 把应用的省电策略设为“无限制”；在最近任务中锁定应用（下滑或点挂锁）。
三星 / One UI设置 > 电池和设备维护 > 电池 > 后台使用限制：从“休眠应用程序”“深度休眠应用程序”移除并加入“永不休眠应用程序”；设置 > 应用程序 > Workday Wake > 电池 > 不受限制。同时确认“让未使用的应用程序进入休眠”是关闭的 — 它可能抑制多日未用应用的闹钟。
华为 / EMUI、HarmonyOS设置 > 电池 > 应用启动方式：设为“手动管理”，打开自动启动、被其他应用启动、后台运行；电池优化：选择“不允许”。
一加 / Oppo / Realme（ColorOS）电池优化：选“未优化”；应用信息 > 电池：“允许后台活动”/“不受限制”；在启动管理器中允许自启动；在 DuraSpeed 中把 Workday Wake 移出被监管列表。
Vivo / iQOO在权限管理器中允许自启动；关闭电池优化；允许后台活动并在最近任务中锁定应用。
Sony设置 > 电池 > STAMINA 模式：“关闭” — 或关掉其“优先使用电池时间”的附加限制。

其他系列（华硕 PowerMaster、魅族、联想、摩托罗拉 Battery care、诺基亚 DuraSpeed、传音/itel/Infinix Phone Master）在应用内也可同样处理： 设置 > 可靠性 会识别你的厂商，只显示适用于你设备的 步骤。所有步骤都以固定的字符串资源存在应用里； 没有硬编码或品牌专属分支。

几乎在所有系统上都有效的技巧：打开最近任务并 锁定 Workday Wake（挂锁图标）。这一步就能避免绝大多数上划杀进程 和内存清理造成的丢失，还能修复点按“跳过”后不再更新的小组件。

设备上的诊断

上面每一项可靠性工程都会在本地留下可检查的痕迹。 在设置 > 诊断中，应用会回答一份错误报告需要问的所有问题：

  • 接入侧：守护进程心跳正常吗？闹钟最后一次排定 是什么时候、预期何时响铃、实际何时响铃？
  • 检测到多少次漏响，应用最后一次自愈 （漏响后重新排定）是什么时候？
  • 应用版本、安卓版本、厂商和型号 — 正是厂商相关行为 发生的地方。
这个界面的一切都在你的设备上计算和存储。诊断是 镜子，不是发射器：应用无法自行上传其中任何内容。

在设置 > 可靠性中还能看到设备所处的保护级别 （“级别 1 / 级别 2”）、累计漏响次数，而且 — 在 受影响的品牌上 — 还有设备电池指南本身。

共享诊断数据 — 自愿，由你决定

如果闹钟失效需要帮助，设置 > 诊断里有 “发送给开发者”的操作：

  1. 这是自愿开启的：发生任何事之前，对话框会列出每一个字段。
  2. 报告只含技术信息 — 时间戳、计数器、版本、厂商/型号。 不含闹钟标签、姓名或任何标识符。
  3. 你选择目的地（电子邮件、即时通讯，任何有分享面板 的都可以）。除非你在草稿上按下发送，否则什么都不会离开设备。
应用中没有任何上传端点、崩溃上报服务或自动后台发送。 如果你不想用分享面板，也备有复制到剪贴板的替代方式。

一切由你掌控

  • 无账号、无数据统计、无广告 — 可靠性 工程只使用设备上的资源。参见 隐私政策。
  • Alarm Guard：保持应用存活的常驻通知服务可以在 设置 > 可靠性中关闭（在限制严格的设备上会损失部分漏响保护）。
  • 级别 2 监控只在命中已知品牌或发生已记录事件后启用额外组件； 绝无任何隐藏的上报渠道。
  • 卸载或清除应用存储就是完全重置：每一个诊断计数器、心跳时间戳 和漏响记录都只存在于你设备的应用存储中。

坦诚的局限

  • 在 AOSP 基线设备上验证，而非所有设备。韧性 设计用 Android 开源项目原语（进程击杀、深度 Doze、 待机分桶）在一次性 Pixel 模拟器上测试，因为只有这些可以自动化。 模拟器无法完全复现小米自启动限制、三星设备维护或厂商的 闹钟节流 — 真实设备表现只能通过 dontkillmyapp.com 指南、 各品牌报告和用户发来的诊断数据来逼近。
  • 不承诺万无一失。激进的厂商会在固件版本之间 更改电源管理。如果某个品牌引入新的杀进程机制，应用可能需要 更新来适配；诊断数据正是我们发现问题的途径。
  • 状态栏的闹钟图标是有意为之 — 它随承载 你闹钟的调度 API 而来。
  • 没有 iOS 版本。上述工程依赖安卓专有 API （合约式闹钟、WorkManager、精确闹钟权限），iOS 没有可 比拟的对应物。

结语

闹钟只有一个职责。Workday Wake 从第一天起就围绕这个职责最难的情形来设计： 它以能在进程死亡中幸存的方式排定， 重建被清除的内容，必要时用第二个进程自监督， 出问题时在设备上如实报告。隐私底线是绝对的 — 这些坦诚不 会牺牲你的任何数据。

发现某个设备上本指南不适用？请 提交 issue， 可能的话用自愿分享功能附上设备上的诊断数据。这条反馈回路 正是模拟器无法替代的东西。
